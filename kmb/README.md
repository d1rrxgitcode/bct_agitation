# Учётная система личного состава

Лёгкое веб-приложение на Node.js (Express) + PostgreSQL для учёта личного
состава формирования: таблица состава, личные дела, документация с гибкой
приватностью, дашборд активностей и админ-панель пользователей.

Без React/сборщиков — фронтенд на чистом HTML/CSS/JS, поэтому приложение
лёгкое и не требует шага сборки на сервере.

## Возможности

1. **Таблица состава** — IDN, позывной, звание и должность (редактируемые
   списки), Steam ID, Discord, активность, подразделение, статус наёмника.
   Сортировка по всем ключевым столбцам, поиск и фильтры. Редактировать
   могут только роли Командир / Заместитель командира / Модератор.
2. **Админ-панель** — создание пользователей, назначение ролей (Командир,
   Зам. командира, Модератор, Военнослужащий), привязка логина к личному
   делу, блокировка/смена пароля. Доступна Командиру и Заместителю.
3. **Личное дело** — оформлено в стиле служебного досье (как на
   скриншоте): идентификационные данные, служебные данные, история званий,
   статус, принадлежность, подчинение.
4. **Документация → Категории → Документы** — категории с гибкой
   приватностью: видна всем / только командованию и модераторам / только
   конкретному подразделению / произвольному набору ролей.
5. **Дашборд** — счётчики агитаций, тренировок, разведок и боевых действий,
   с журналом записей и фильтром по типу.

Тема оформления (светлая/тёмная) переключается в любой момент и сохраняется
в браузере пользователя. Цветовая гамма — бело-серая (без синего/зелёного).

## Стек

- Node.js + Express
- PostgreSQL (через `pg`, без ORM)
- Сессии — `express-session` + `connect-pg-simple` (хранятся в той же БД)
- Пароли — `bcryptjs`
- Фронтенд — статические HTML/CSS/JS без сборки

## Установка на VPS

### 1. Предустановки

```bash
# Node.js 18+ и PostgreSQL должны быть установлены на сервере
sudo apt update
sudo apt install -y postgresql nodejs npm
```

### 2. База данных

```bash
sudo -u postgres psql -c "CREATE USER roster_user WITH PASSWORD 'надёжный-пароль';"
sudo -u postgres psql -c "CREATE DATABASE roster_db OWNER roster_user;"
```

### 3. Приложение

```bash
# Распакуйте архив на сервере, затем:
cd republic-roster
npm install --production
cp .env.example .env
nano .env   # укажите DATABASE_URL, SESSION_SECRET, ADMIN_USERNAME/ADMIN_PASSWORD

npm run migrate   # создаёт таблицы, справочники по умолчанию и первого командира
npm start          # запуск на порту из .env (по умолчанию 3000)
```

Откройте `http://ваш-сервер:3000/login.html` и войдите под логином/паролем
из `.env` (ADMIN_USERNAME/ADMIN_PASSWORD). **Сразу смените пароль** через
Админ-панель.

### 4. Постоянная работа (рекомендуется PM2)

```bash
npm install -g pm2
pm2 start server/index.js --name roster
pm2 save
pm2 startup
```

### 5. Домен и HTTPS (опционально, через nginx)

Проксируйте порт приложения через nginx + certbot и в `.env` выставите
`COOKIE_SECURE=true`, чтобы сессионные cookie передавались только по HTTPS.

## Структура проекта

```
republic-roster/
  db/
    schema.sql      — структура таблиц
    seed.sql         — справочники по умолчанию (звания/должности/подразделения)
    migrate.js       — применяет schema+seed, создаёт первого пользователя
  server/
    index.js         — точка входа Express
    db.js             — подключение к PostgreSQL
    middleware/auth.js — проверка сессии и ролей
    routes/           — auth, personnel, lookups, docs, activities, admin
  public/
    css/style.css     — светлая/тёмная тема, бело-серая гамма
    js/                — логика каждой страницы (без фреймворков)
    *.html             — страницы приложения
```

## Роли и права

| Роль                     | Просмотр состава | Редактирование состава | Документация (свои категории) | Админ-панель |
|--------------------------|:---:|:---:|:---:|:---:|
| Командир (commander)     | ✔ | ✔ | ✔ (видит всё) | ✔ |
| Зам. командира (deputy)  | ✔ | ✔ | ✔ (видит всё) | ✔ |
| Модератор (moderator)    | ✔ | ✔ | ✔ | ✖ |
| Военнослужащий (member)  | ✔ | ✖ | по настройке категории | ✖ |

## Категории документации — приватность

При создании/редактировании категории можно выбрать:
- **Всем** — видят все авторизованные пользователи;
- **Командование + модераторы** — только роли commander/deputy/moderator;
- **Конкретное подразделение** — видят только участники выбранного
  подразделения (по привязке пользователя к личному делу);
- **Особые роли** — вручную выбранный набор ролей.

Командир и Заместитель командира всегда видят все категории.

## Резервное копирование

Все данные лежат в PostgreSQL, поэтому достаточно штатного `pg_dump`:

```bash
pg_dump -U roster_user roster_db > backup.sql
```
